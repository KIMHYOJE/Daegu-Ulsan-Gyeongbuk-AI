1. 문제 정의 — 보내기 직전, 사람이 눈으로 확인하는 일

지금 하는 일

  • 대출 심사·제출 서류를 다른 기관이나 고객에게 보내기 전에 담당자가 쪽마다 번호를 찾아 가렸는지 확인
  • 한 묶음에 개인 서식과 법인 서식이 섞여 옴: 원천징수영수증, 동의서, 재무제표, 주주 명세, 사업자등록증
  • 번호가 칸마다 한 글자씩 나뉘어 적힌 법정 서식이 많아 훑어보면 놓침

실제로 새는 지점

  • 신청자 칸은 가렸는데 배우자 칸은 그대로
  • '개인정보 마스킹 처리본' 표시만 믿고 남은 급여 금액을 놓침
  • 법인 서류(주주 명세) 안의 개인 주주 주민등록번호
  • 휴대폰으로 찍은 흐린 사본 — 읽지 못한 것을 "없음"으로 처리

목표: 1차 점검을 자동으로 하고, 확실하지 않은 건은 추측하지 않고 담당자에게 넘긴다

4. 신뢰성 설계 — 틀리기 쉬운 상황을 미리 막기

틀릴 수 있는 상황막는 방법나오는 값
흐린 촬영본이라 번호를 못 읽음readability=unclear면 검증 빨강. 제목·이름·항목이 전부 비면 '읽지 못함'으로 봄검토 필요
이름만 가리고 회사·직위·출생연도가 남음재식별 위험으로 담당자에게 넘김검토 필요
'마스킹 처리본' 표시가 있음표시를 믿지 않고 모든 칸을 같은 기준으로 다시 봄남은 값 기준
신청자 칸만 가리고 배우자 칸은 그대로한 칸이라도 전체 값이면 노출고위험
가린 값을 노출로 셈출력 전 자기 점검: 가림 없는 값을 근거로 인용할 수 없는 항목은 뺌등급 재계산
법인 손익계산서의 '급여'개인 소득정보가 아니라 기업재무정보로만 봄기업재무정보

사람에게 넘기는 장치: 결정값 '검토 필요' → 담당자 확인 메모 + 고객 재제출 요청문 자동 작성
