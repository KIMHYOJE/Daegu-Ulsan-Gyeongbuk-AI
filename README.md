# 금융문서 민감정보 위험도 등급화 — 요미의 코딩

IM뱅크 지정주제 「AI 기반 금융 문서 민감 정보 자동 식별 및 위험도 등급화」 최종 제출물입니다.
은행 서류를 밖으로 보내기 전에 가려지지 않은 민감정보를 찾아 **고위험 · 중위험 · 저위험 · 검토 필요** 4단계로 1차 판정하고, 등급별 후속 조치문을 작성하는 Upstage AI Studio 워크플로우입니다.

- 소개 사이트: https://yomicoding-site.vercel.app — 샘플 PDF나 직접 올린 PDF를 AI로 판정하고, 노출된 값을 검게 가린 PDF를 내려받을 수 있음
- 결과: 정답 데이터셋 20개 묶음 중 Studio 워크플로우 19개 일치(set15 불일치), 소개 사이트 AI 판정 20개 일치 (위험도·노출 항목·정보 주체 3개 키가 모두 같아야 일치)

## 우리가 문제를 푼 방법

### 1. 문제를 좁힘 — "보내기 직전, 사람이 눈으로 확인하는 일"
대출 심사 서류를 다른 기관이나 고객에게 보내기 전에 담당자가 쪽마다 번호를 가렸는지 확인하는 일을 대상으로 잡았습니다. 실제로 번호가 새는 지점을 먼저 적었습니다.

- 신청자 칸은 가렸는데 **배우자 칸**은 그대로 남음
- '개인정보 마스킹 처리본' 표시만 믿고 남은 **급여 금액**을 놓침
- 법인 서류(주식등변동상황명세서) 안의 **개인 주주 주민등록번호**
- 법정 서식은 번호를 **칸마다 한 글자씩** 적어서 훑어보면 놓침
- 휴대폰으로 찍은 흐린 사본에서 못 읽은 번호를 "없음"으로 처리

목표는 "1차 점검은 자동으로, 확실하지 않은 건 추측하지 않고 담당자에게 넘긴다"로 정했습니다.

### 2. 판정 기준을 말이 아닌 조건으로 고정
"민감해 보이면 고위험" 같은 표현은 실행마다 결과가 달라서, 개수와 목록으로 바꿨습니다.

- **노출** = 마스킹 문자(`*` `X` `●` `○`)가 하나도 없는 전체 값
- **고위험**: 주민등록번호·외국인등록번호·여권번호·운전면허번호·카드번호 중 1개 이상 노출
- **중위험**: 고위험 0개이고 계좌번호·휴대전화번호·주소·이메일·소득정보·신용정보·기업재무정보 중 1개 이상
- **저위험**: 노출 0개
- **검토 필요**: 판독 불가 문서가 1개 이상, 또는 가린 이름 + 회사명·직위·출생연도가 함께 있음(재식별 위험)
- 판정 순서는 검토 필요 → 고위험 → 중위험 → 저위험으로 고정하고, 묶음 전체에서 가장 높은 등급 하나만 냅니다.
- 사업자·법인등록번호, 사업장 주소, 자본금, 대표자 생년월일은 공개 정보라 항목에서 뺐습니다. 법인 손익계산서의 '급여'는 개인 소득이 아니라 기업재무정보로 봅니다.

### 3. 사람이 하던 순서를 노드로 옮김
| 순서 | 노드 | 넣은 이유 (없으면 생기는 문제) |
|---|---|---|
| 1 | Parse (OCR 강제) | 촬영·스캔본은 글자층이 없어 빈 문서로 읽힘 → '노출 없음 → 저위험'으로 잘못 나감 |
| 2 | Classify (서식별 분할) | 한 PDF에 서식이 최대 3종 이어져 옴. 나누지 않으면 서식마다 값이 섞임 |
| 3 | Extract (18개 항목) | 원문 전체를 한 번에 판단하면 가린 `900101-1******`을 노출로 세거나 칸마다 나뉜 번호를 놓침. 마스킹 문자는 그대로 옮기게 함 |
| 4 | Merge | 판정 단위가 발송 1건(PDF 1개)이라 문서별 결과를 하나로 합침 |
| 5 | Validate | 판독 상태 `clear` 필수, 주민등록번호 신뢰도 0.8 이상. 못 읽은 번호를 '없음'으로 보지 않게 함 |
| 6 | Instruct 위험도_판정 | 출력 키 4개(risk_level, detected_items, data_subject, reason)를 내고 결정값으로 분기 |
| 7 | Instruct ×4 | 고위험 발송차단_보고 / 중위험 마스킹_요청 / 저위험 발송승인_기록 / 검토 필요 담당자_확인요청 |

### 4. 데이터셋을 실제 서식으로 만듦
- 국가법령정보센터의 별지 서식 원본(`mission2_build/forms/`)에 가상 값을 채웠습니다: 근로소득 원천징수영수증, 금융정보 등 제공 동의서, 여권 발급 신청서, 외국인등록사실증명, 표준재무상태표, 표준손익계산서, 주식등변동상황명세서, 사업자등록증.
- 번호는 가상임이 보이게 0을 채웠습니다(예: `900101-1000017`, `010-0000-2847`).
- 위 1번의 "새는 지점"을 하나씩 묶음으로 만들었습니다: 배우자 칸만 노출(set09), 마스킹 처리본 도장 + 남은 소득(set16), 법인 서류 + 대표자 동의서(set17), 흐린 휴대폰 촬영본(set07), 모두 가린 묶음(set15) 등.
- 정답 분포: 고위험 9 · 중위험 6 · 저위험 3 · 검토 필요 2. 유형표에 유형 ①~⑤를 모두 넣었습니다.
- 스크립트: `mission2_build/fill_cases.py`(PDF 생성), `build_final_meta.py`(answer.json·유형표)

### 5. 틀린 결과를 보고 한 가지씩 고침
14개 묶음으로 먼저 돌려 보고, 틀린 케이스의 근거(reason)를 읽어 원인을 찾은 뒤 설정을 하나씩 바꿨습니다.

| 설정 | 일치 | 고친 점 |
|---|---|---|
| #4 | 11/14 | 법정 서식 기준으로 분류·추출 설명 교체 |
| #5 | 13/14 | 흐린 사진 '판독 실패' 규칙 추가, `○`를 마스킹 문자에 추가 |
| #6 | 13/14 | 서식 2종이 한 범위로 묶여도 모든 쪽을 읽도록 추출 지시 수정 |
| #7 | 13/14 | 출력 전 자기 점검 추가(가림 없는 값을 근거로 인용할 수 없는 항목은 뺌) |
| #8·#9 | 14/14 | 목록 값을 첫 값만 보지 않고 하나씩 모두 확인 |
| 최종 (#1) | **19/20** | 같은 설정을 최종 에이전트로 옮기고 묶음을 20개로 늘려 전체 실행 |

남은 불일치 1건(set15)은 번호를 모두 가린 묶음인데, 근거에는 "노출 항목 없음"이라 쓰고 등급은 중위험으로 냈습니다. 다음 단계로 "근거와 등급이 어긋나면 검토 필요로 넘기는" 점검을 넣을 계획입니다.

### 6. 누구나 써 볼 수 있게 사이트로 만듦
- `api/grade.js`(Vercel 함수): Upstage Document Parse(OCR 강제) + 줄 단위 OCR → Solar(solar-pro4)로 칸별 값 추출 → Studio와 같은 규칙을 코드로 적용해 판정. 추출은 AI, 등급은 규칙으로 나눠 결과가 흔들리지 않게 했습니다.
- API 키는 서버 환경변수(`UPSTAGE_API_KEY`)에만 두고 방문자는 키를 넣지 않습니다.
- **가린 PDF 만들기**: OCR 단어 좌표로 노출된 값의 위치를 찾아 검게 칠하고, 쪽을 그림으로 바꿔 가린 글자가 남지 않게 했습니다. '항목명 + 숫자'는 숫자만 가립니다.
- 판정 근거 화면에 노출/가림 값과 판정 단계(1-a 판독 불가 → 4 저위험)를 보여 줍니다. 샘플 20개를 한꺼번에 판정하면 20개 모두 정답과 같았습니다.
- 겪은 문제: PDF 폰트를 통째로 넣어 파일이 7~22MB가 되어 Vercel 요청 한도(4.5MB)를 넘음 → 폰트 서브셋으로 0.15~0.5MB로 줄임.

### 7. 데모 영상
Playwright로 Edge 화면(1440×900)을 직접 녹화하고, FFmpeg로 장면을 자르고 대기 시간을 빠르게 감은 뒤 단계별 자막을 넣었습니다. 순서: Studio 결과 표 → set17의 Parse·Classify·Extract·Validate·판정·후속 문서 → 사이트에서 set09 판정 → 가린 PDF. 만드는 스크립트는 `mission2_build/demo_video/`에 있습니다.

## 데이터 안내

모든 PDF는 국가법령정보센터의 법정 서식에 **가상 값**을 채운 것입니다. 실제 고객 정보는 들어 있지 않습니다.
